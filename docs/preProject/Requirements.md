# DEVELOPMENT PRINCIPLES

Always:

* Explain architectural decisions.
* Create clean folder structures.
* Keep functions small.
* Prefer composition over inheritance.
* Use Domain Driven Design where reasonable.
* Follow SOLID principles.
* Write production-quality code.
* Add proper logging.
* Add error handling.
* Add tests when appropriate.
* Avoid magic strings.
* Avoid duplicated logic.
* Keep APIs RESTful.

Whenever implementing a feature:

1. Explain the feature.
2. Explain the architecture.
3. Suggest database schema changes.
4. Suggest API endpoints.
5. Suggest UI.
6. Suggest future improvements.
7. Then generate the code.

Never jump directly into implementation.
